### REQ-002: BLE OTA 技术方案升级——采用 Espressif 官方 ble_ota 组件

- **状态**: 进行中
- **描述**: 用户指示"OTA 检索开源健康库，不要从零手搓"。调研结论：采用 espressif/ble_ota v0.1.17（esp-iot-solution 官方组件）
- **调研要点**（来源：WebSearch/WebFetch 交叉验证）:
  - **协议层**：官方组件自带——每 4KB sector CRC16、命令包 CRC16、ACK 主动指定期望 Sector_Index（断点续传语义内建）
  - **服务**：OTA Service 下 4 特征：RECV_FW 0x8020（Write+Notify）、PROGRESS 0x8021、COMMAND 0x8022、CUSTOM 0x8023
  - **命令包**（0x8022，20B 定长）：Command_ID(2B) + Payload(16B) + CRC16(2B)；0x0001 Start(size)、0x0002 Stop、0x0003 ACK、0x0004 ?
  - **数据包**（0x8020，MTU 变长）：Sector_Index(2B) + Packet_Seq(1B) + Payload；Packet_Seq=0xFF 表 sector 尾包且尾 2B 为该 4KB sector 的 CRC16
  - **ACK**（0x8020 notify，20B）：Sector_Index(2B)+Status(2B)+CRC16(2B)；0x0002=sector 错且附期望号 → 续传依据
  - **回滚**：CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE=y + esp_ota_mark_app_valid_cancel_rollback()；PENDING_VERIFY 状态下 esp_ota_begin 会拒绝 → OTA 服务必须在 mark valid 之后才开
  - **断点续传设备端**：IDF v6 新 API esp_ota_resume(partition, erase_size, image_offset, out_handle)（不擦分区续写）+ NVS 持久化 {offset, image_size} 每 4KB 更新
  - **否决 fbiego/ESP32_BLE_OTA_Arduino**：无 CRC、无续传、Arduino 三层专有依赖（SPIFFS/FFat/Update）需全部重写、2024-08 停更
  - **上位机**：无现成 Python 客户端，用 Bleak 照官方协议自写（协议为纯字节帧）
- **影响范围**: firmware/、host/（全新）
