### ERR-012: hxd019 组件在 IDF v6 下的三连编译错误（driver 拆分/API 更名/无效语句）

- **症状**: WSL 临时自测工程构建失败，连续三个错误：
  1. `hxd019_uart.c includes driver/uart.h, provided by esp_driver_uart`（组件依赖提示性报错）
  2. `implicit declaration of function 'uart_wait_tx_done_polling'`（-Werror）
  3. `statement with no effect` 在 mut_temp 的"防呆 no-op"行（-Werror=unused-value）
- **根因**:
  1. IDF v6 把 monolithic `driver` 组件拆成 esp_driver_uart/esp_driver_gpio 等，组件 CMakeLists 写 `PRIV_REQUIRES driver` 在 v6 已不解析 uart 头
  2. v6 的 UART 轮询等待 API 是 `uart_wait_tx_idle_polling()`，`uart_wait_tx_done_polling` 从未存在于 IDF（ESP8266/其他 SDK 的 API 名混淆）
  3. 写了一个"表达式语句当注释用"的 no-op（`((struct u8_arg *)arg)->val;`），纯值读取无副作用，触发 -Wunused-value → -Werror
- **修复**: ① PRIV_REQUIRES 改 `esp_driver_uart`；② 改用 `uart_wait_tx_idle_polling()`；③ 删除 no-op 行
- **规律提炼**: ① 在 IDF v5→v6 迁移中，所有 `REQUIRES driver` 的老写法都要按实际外设拆分重写（uart→esp_driver_uart, gpio→esp_driver_gpio...）；② 跨 SDK 写驱动时 API 名以目标 IDF 版本头文件 grep 为准，不凭记忆；③ 任何"占位/防呆"表达式语句都会被 -Werror 拦截，占位就用真正的 `/* 注释 */` 或 `(void)x;`
- **二次提炼接口**: 组件首次参与编译（之前只跑过未被引用的主工程构建）时，必须逐个 -Werror 级编译错误清零；ESP-IDF 升级大版本后，先 grep IDF 组件目录确认 API 存在性再写调用
- **首次出现**: 2026-09-03
- **复现次数**: 1
