### ERR-006: 固件广播名竞态——真机空中广播名为组件硬编码 "nimble-ble-ota" 而非 "C6-OTA-1128"

- **症状**: 上位机 BleakScanner 实测（Windows 真实蓝牙环境）：设备 14:C1:9F:E5:11:2A 空中广播名为 `nimble-ble-ota`（组件 host_init 里设置的默认名），不是 `C6-OTA-1128`。TASK-002 验收时的 "adv C6-OTA-1128" 锚点日志只证明 GAP 名已设置（`ble_svc_gap_device_name()` 返回值），不等于空中广播数据用了这个名字
- **根因**: ble_ota 组件 `esp_ble_ota_on_sync()` 回调（nimble_ota.c:1112-1136，host 协议栈同步完成时触发，异步于 app_main）内部调用 `esp_ble_ota_advertise()`，其中**实时读取** `ble_svc_gap_device_name()` 构造广播 fields。firmware/main/main.c:134-138 的顺序是 `esp_ble_ota_host_init()`（内部启动 NimBLE host task）→ 立即 `ble_svc_gap_device_name_set("C6-OTA-1128")`，注释假设 host 同步"需完成多轮 HCI 命令（毫秒级）必然慢于 name_set"。本机实测该假设不成立：host 同步（可能因缓存/时序）先于 name_set 完成广播构造，广播数据定格为旧名 "nimble-ble-ota"。BLE 广播名在 adv fields 构造那一刻固化，之后改 GAP 名不影响已启动的广播
- **修复**: 固件侧（待办，不在本任务范围）：name_set 必须挪到 host_init **之前**（NimBLE GAP 服务初始化前设置名字是否生效需验证；稳妥方案是自定义 adv：等待 ble_gap_adv_active 后停广播→改名→重启广播；或用 ble_hs_sync_callback 先注册同步回调，同步后再 set name 并手动起广播）。上位机侧已做兼容：find_device 支持 --mac 按 MAC 匹配、scan 同时列出 nimble-ble-ota 别名
- **规律提炼**: "先 init 后配置"的时序假设必须以**空中/输出侧的最终消费时机**为准验证，不能以函数返回顺序推断。异步框架里 init 函数返回 ≠ init 的回调链执行完毕；凡"回调里读取配置"的模式，配置必须先于 init 或等待同步点后再改。日志锚点打印的是"软件视角状态"，与"外部视角真实表现"（空口抓包/对端所见）是两回事，验收必须看后者
- **二次提炼接口**: META 规则 —— [ASYNC] 组件/库在异步回调中读取全局配置时，app 侧配置写入必须先于 init 调用，或挂接到同步点之后；禁止用"我的写操作在函数返回前"推断竞态胜出。验收外设行为以对端/空口实测为准
- **首次出现**: 2026-09-01
- **复现次数**: 1（首现即空中实测捕获）
