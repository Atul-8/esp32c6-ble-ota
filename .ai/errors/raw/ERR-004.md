### ERR-004: Gitee API POST /repos/{owner}/{repo}/issues 返回 404 "project or enterprise"

- **症状**: 用 git 凭据管理器里的 Gitee token（waterguy）调 v5 API 创建 issue，GET /issues 返回 200 空列表，POST 却 404 `{"message":"project or enterprise"}`；JSON body、form body、query 参数、Bearer header、数字 repo id 路径、旧版路径 `/repos/{owner}/issues/{repo}`（405）全部尝试无效；新老仓库都一样
- **根因**: Gitee 个人访问令牌（PAT）按 scope 授权。git https 推送用 token 通常只勾 `projects` scope；**POST issue 需要 `issues` scope**。Gitee 对无权限的写操作不返回 403 而是伪装 404（且错误信息误导性地提到 enterprise）
- **修复**: 短期——issues 迁到 GitHub（token scope: repo,workflow,gist，够用）；长期——用户在 Gitee 设置→私人令牌 勾选 `issues` scope 重新生成，脚本 tools/create_issues.py 即可对 Gitee 复用
- **规律提炼**: Gitee API 的 404 有两种含义：资源不存在 和 **scope 不足**。排查顺序：GET 同资源 → 换认证方式（header/body）→ 换路径变体 → 都通但 POST 404 = scope 问题
- **二次提炼接口**: META 规则 —— [API_CONTRACT] Gitee API POST 404 "project or enterprise" = token 缺对应 scope（非资源不存在）；GET 200 + POST 404 组合是特征指纹。建库前先确认 PAT 勾选了 issues + projects 双 scope
