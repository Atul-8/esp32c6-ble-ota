### ERR-005: ble_ota 组件链接期 undefined reference to `notify_sem`

- **症状**: 引入 espressif/ble_ota v0.1.17 组件后链接失败：`nimble_ota.c.obj: undefined reference to notify_sem`（ble_ota_start_write_chr 内 3 处引用）。组件头文件与文档均未提及该符号
- **根因**: 组件 Stop 命令（`02 00`）处理器里有 `extern SemaphoreHandle_t notify_sem;` 并 take/give 该信号量——组件反向依赖 **app 侧定义的非 static 全局符号**。这是组件的隐式 app 侧契约：官方 example 的 `SemaphoreHandle_t notify_sem;`（无 static）恰好满足。任何把信号量做成 static 或改名的 app 都会链接失败；且头文件没有任何提示，只能靠链接器暴露
- **修复**: app 侧（firmware/main/ota_task.c）保持与 example 相同的非 static 全局定义 `SemaphoreHandle_t notify_sem = NULL;` 并加注释说明原因
- **规律提炼**: 第三方组件链接错误 `undefined reference to <小写蛇形符号>` 时，先 grep 组件源码找 `extern <符号>`——可能不是自己漏了库，而是组件要求 app 提供符号（反向依赖/回调钩子）。对接官方 example 的代码时，example 里"看似随意"的非 static 全局可能就是这种契约，不可随手 static 化
- **二次提炼接口**: META 规则 —— [DEPENDENCY] 引入第三方组件出现 undefined reference 时，先在组件源码 grep `extern <符号>`：命中则该符号需由 app 全局定义（隐式契约）；改造 example 代码时禁止 static 化任何被组件 extern 引用的符号
- **首次出现**: 2026-09-01
- **复现次数**: 1
